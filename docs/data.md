# Data

## Fixture v1

Generated by `tools/make_fixture.py --rows 4000 --seed 42` into
`examples/fixtures/v1/complaints_synthetic.csv`. Authored synthetic demonstration data;
fictional identifiers; not derived from any person, company, account or dataset.

Design choices, all visible in `src/complaint_intelligence_lab/cfpb/synthetic.py`:

- 8 products with public-taxonomy names, 2 to 3 issues each, weights skewed so that
  Credit reporting is the largest class.
- Narratives are 1 to 3 product-specific template sentences, optionally prefixed with a
  time phrase, plus 0 to 2 generic sentences shared by every product. 30 percent of
  narratives replace their first sentence with an ambiguous one that fits several
  products, so the label is not always readable from the text.
- About 5 percent empty narratives.
- About 3 percent exact and 3 percent near-duplicate narratives injected by copying
  another row of the same product (near duplicates append one generic sentence).
- A volume increase for `Money transfer / Fraud or scam` in the last three months, so the
  trend module has a known target.
- Six obviously fictional companies, 15 US state codes, four submission channels.
- `company_response`, `timely`, `consumer_disputed` are populated so the leakage guard has
  something to refuse.

Observed on the generated file (computed by `make demo`, seed 42): 4,000 rows,
2024-07-01 to 2026-06-30, 4.7 percent empty narratives, 459 exact and 231 near-duplicate
pairs forming 407 groups that cover 1,097 rows.

## Real data path

`python -m complaint_intelligence_lab fetch --date-min ... --date-max ... --yes` calls the
public API, projects each record to the structured columns, drops the narrative unless
`--include-narrative` is given, and writes a JSON cache with `downloaded_at`, the request
parameters and the data-use URL. Caches live under `data/` which is git-ignored. Tests use
an injected fake transport and never call the network.

The API returns complete records; column minimisation happens client-side before the cache
is written. This is stated in the client docstring so nobody assumes the provider filtered
the fields.

## Schema validation

`cfpb/schema.py` requires `complaint_id`, `date_received`, `product`, `issue`; parses dates
and fails on any unparseable value (the split depends on them); fills the narrative with an
empty string when absent; and rejects duplicate `complaint_id` values.
